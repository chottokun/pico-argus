# コグニティブ・フォーカストラッキング・エッジシステム 実施成果ウォークスルー (V2.1 - V2.2)

本ドキュメントは、Tapo カメラを用いた自律型追従および能動知覚（Active Perception）エッジシステムにおける課題解決、仕様拡張、および動作検証の成果を取りまとめた完了報告書である。

## 🎯 達成された主要な改善成果

### 1. アノテーション枠線・文字の焼き込み（汚染）による VLM 誤認の完全解消
- **課題**: YOLO の検出枠（緑色のバウンディングボックス）や `person#34` 等の描画ラベル、PID の中央交差ラインが描画された後の映像フレームを VLM（Ollama）へ送っていたため、VLMが「画像に緑の枠線や測定用の線が描かれており、製品の寸法測定・物流管理プロセスが行われている」と誤認識（ハルシネーション）を起こしていた。
- **対策**: YOLO や PID の描画処理が行われる直前に、オリジナル画像の純粋なコピー（`frame_clean`）を退避。VLM の画像クロップ解釈（`analyze_crop_image`）には、この汚染されていないクリーンフレームのみを切り出して供給する仕組みへ修正。
- **検証結果**: VLMが描画マーカーに一切左右されず、「黒の半袖Tシャツ」「眼鏡」「黒のオーバーイヤー型ヘッドホン」「右を向いて座った姿勢」のみを 100% 正確に認識可能になった。

### 2. トラッカーIDごとの Wiki ファイル増殖防止とカテゴリ統合追記（Append）の実現
- **課題**: 通過する人物に割り当てられた一時的なトラッカーID（例: `person_16`, `person_18`）ごとに新しい Markdown ファイルが生成され、`wiki/` フォルダ内に不要なファイルが無限増殖していた。
- **対策**: 一時的ID単体でのファイル作成を禁止し、`observed_people` (観測された人物) などの**カテゴリごとに統合されたファイル名**を使用するルールへ変更。`memory-cli` およびツール内部で既存ファイルが存在する場合は Frontmatter（YAML メタデータ）を保ったまま、本文末尾に `### 🕒 観測記録: YYYY-MM-DD HH:MM:SS` のヘッダー付きで時系列に自動追記するコンソリデーション機構を導入。
- **検証結果**: 人物が繰り返し検出された際も、[wiki/auto_observed_people.md](file:///e:/Python%20Scripts/Pico/wiki/auto_observed_people.md) という単一のドキュメント内に時系列でログが正しく蓄積・永続化されることを実証。

### 3. 多重プロセス起動による Tapo カメラセッション干渉・フリーズの解消
- **課題**: 画面モニター用の手動スクリプト `scratch/run_live_system.py` と、エディタのバックグラウンドプロセスとして稼働する MCP サーバー（`cognitive-surveillance-mcp`）が二重に起動していたことで、Tapo カメラの RTSP / ONVIF セッション上限を超え、映像ストリームおよび追従制御がフリーズしていた。
- **対策**: プロセス競合を排除し、MCP サーバー自身が持つ自律追従制御（`set_tracking_target`）および各種 MCP ツール経由での操作のみに一本化。
- **検証結果**: プロセスの衝突がなくなり、BBOXのフリーズや物理追従の途切れが完全に解消され、極めて安定した能動知覚動作を実証。

### 4. Ollama VLM 連続リクエスト時のタイムアウト（ReadTimeout）防止
- **課題**: 高負荷な画像クロップ解析（VLM）を実行した直後、連続してテキスト推論リクエストが飛ぶと、Ollama 側でリソース解放が間に合わずタイムアウト（ReadTimeout）およびアボートが発生していた。
- **対策**: クライアント側のタイムアウト上限を `120.0` 秒に延長し、かつ VLM 解析直後に 1.5 秒の非同期クールダウン時間を挿入。
